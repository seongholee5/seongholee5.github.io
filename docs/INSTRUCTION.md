## 1. 기본 방향

- 학술 홈페이지다운 절제된 구성, 흰 배경과 서울시립대를 연상시키는 남색·파란색을 사용한다.

- 같은 역할의 텍스트·간격·구분선에는 공통 CSS 변수를 사용한다. 화면별로 임의의 글자 크기나 개별 예외를 만들지 않는다.
- 상단에 작은 Home / Profile / Research / Lab 표제를 중복해서 넣지 않는다. 장식적인 IDEA 로고나 최상단 파란 선을 추가하지 않는다.
- 넓은 화면(>900px)에서는 Home·Profile·Research·Lab 네 페이지에 프로필을 공유하며 sticky 동작을 유지한다. 좁은 화면(≤900px)에서는 Home에만 가운데 정렬된 프로필을 표시하고 Profile·Research·Lab은 메뉴 아래에서 바로 본문을 시작한다. 독립된 `/cv`에는 화면 폭과 무관하게 메뉴·사진·사이드바 프로필·사이트 푸터가 없다.
- 실제로 적용된 규칙만 이 문서의 기준값으로 기록한다. 제안만 한 수치는 적용된 것으로 취급하지 않는다.
- 콘텐츠 업데이트 시 기존 디자인을 유지한다. 마지막 추가 제안은 미적용 상태이며 자동으로 진행할 작업이 아니다(11절).

### 링크 역할별 색상과 반응

아래는 홈페이지 화면 기준이다. 모든 링크를 같은 기본색으로 바꾸지 않고 공통 팔레트 안에서 역할을 나눈다.

| 역할 | 기본 상태 | hover 상태 | 별도 표시 |
|---|---|---|---|
| Scholar·CV·Email, Back to top | 파랑 `--blue` | 남색 `--navy` + 텍스트 밑줄 | 아이콘이 있는 경우 아래 이동 규칙 적용 |
| Welcome 지도교수 이름·Research 논문 제목·Recent News 저널명 | 남색 `--navy`, 굵기 600 | 파랑 `--blue` + 텍스트 밑줄 | 제목의 크기·굵기 유지 |
| 상단 비활성 메뉴 | 회청색 `--muted`, 굵기 400 | 파랑 `--blue`, 굵기 400 유지 | hover만으로 선택 표시선을 만들지 않음 |
| 현재 페이지 메뉴 | 파랑 `--blue`, 굵기 600 | 동일 | 아래 2px 파란 표시선과 `aria-current="page"` 유지 |
| 왼쪽 사이트 표제(워드마크) | 남색 `--navy` | 색상 변화·밑줄 없음 | 클릭하면 `/`로 이동 |

- 일반 링크, Welcome 지도교수 이름, Research 논문 제목, Recent News 저널명 링크의 밑줄은 **1px, 글자 아래 4px**이다. 색상 전환은 **0.18초**이며 상단 메뉴도 같은 전환 시간을 쓴다. hover로 글자 크기·굵기를 바꾸지 않는다.
- 프로필·지도교수·논문 링크 아이콘은 오른쪽 1px·위쪽 1px, Back to top 화살표는 위쪽으로만 1px 이동한다. 전환 시간은 0.18초이다.
- 프로필 텍스트는 `.profile-link-label`, Back to top은 링크 안의 `<span>`에만 밑줄을 준다. 아이콘과 빈 공간에 선이 생기지 않도록 이 구조를 유지한다. Email은 `<button>`이므로 hover 대상에서 빠뜨리지 않는다.
- 키보드 `focus-visible`은 모든 링크·버튼에 2px 파란 윤곽선, 바깥 간격 5px를 표시한다. 프로필과 Back to top에는 밑줄도 표시한다. 현재 지도교수·논문 링크의 밑줄과 색상 변화는 hover에만 적용된다.
- `prefers-reduced-motion: reduce`이면 색상·아이콘 전환 애니메이션과 부드러운 스크롤을 끈다. hover의 최종 색상·밑줄·이동 상태 자체는 유지한다.

### 폰트 로딩 — 대체 글꼴이 먼저 보이는 현상 방지

`app/fonts/cormorant-garamond/`에 필요한 두 WOFF2와 OFL 라이선스를 보관한다.

- `cormorant-garamond-semibold.woff2`: 일반체 600.
- `cormorant-garamond-semibold-italic.woff2`: 저널명 이탤릭 600.
- `app/globals.css`의 상대 URL에 **`?inline`**을 붙인다. Vite가 배포 CSS 안에 두 파일을 data URL로 포함하므로 별도의 폰트 다운로드를 기다리지 않는다. 다른 굵기·서체는 추가하지 않는다.
- 두 `@font-face` 모두 **`font-display: block`**을 사용한다. 짧은 디코딩 대기 중 대체 글꼴을 먼저 보여주지 않는다. Arial 본문은 그대로 표시된다. 글꼴 자체가 사용할 수 없으면 브라우저의 대체 글꼴로 복구된다.
- 외부 폰트 파일 preload는 제거한 상태이다. 일반·이탤릭 모두 이미 CSS에 포함되므로 이전 `/fonts/...` preload를 되살리지 않는다.
- 원인은 필요 없는 글꼴의 로딩이 아니라 Georgia → Garamond 교체였다. `swap`으로 되돌리거나 최종 크기·굵기를 바꿔 보정하지 않는다.
- 빌드된 CSS가 원본 두 WOFF2와 동일한 데이터를 포함하는지는 `node scripts/check-font-assets.mjs`로 검증한다. 빌드 후 실행한다.
- 이 방식은 글꼴 약 46KB를 CSS에 포함하는 대신 추가 폰트 요청을 없앤다. 폰트 교체 시 파일 경로·굵기·스타일과 이 검증을 함께 갱신한다.

## 5. 화면 폭과 레이아웃

홈페이지 네 페이지의 CSS breakpoint는 **900px, 560px 두 개**이다. 대화에서 말한 '좁은 모드'는 561–900px, '가장 좁은 모드'는 ≤560px에 해당한다. 문서의 '중간 화면'은 좁은 모드, '모바일'은 가장 좁은 모드와 같은 의미이다. 폭은 브라우저의 CSS px 기준이며 확대된 스크린샷의 픽셀 수와 다르다. `box-sizing: border-box`를 사용한다. `/cv`의 독립 레이아웃은 7절을 따른다.

| 항목 | 넓은 모드 >900px | 좁은 모드 561–900px | 가장 좁은 모드 ≤560px |
|---|---|---|---|
| 사이트 최대 폭 | 1200px | 동일 상한 | 동일 상한 |
| 좌우 여백 | 32px | 24px | 24px |
| 본문 위 / 아래 여백 | 48 / 32px | 32 / 24px | 24 / 24px |
| 메뉴바 높이 | 80px | 72px | 100px, 표제·메뉴 2줄 가운데 정렬 |
| 메뉴 사이 간격 | 32px | 24px | 기본 24px, 328px 미만에서 축소 |
| 프로필 표시 페이지 | Home·Profile·Research·Lab | Home만 | Home만 |
| 프로필 배치 | 왼쪽 200px 열 | 상단 가로 묶음, 가운데 | 상단 가운데, 공간 부족 시 세로 |
| 사진 테두리 포함 폭 | 200px | 144px | 144px |
| 사진 프레임 내부 padding | 6px | 4px | 4px |
| 프로필 정보 열 폭 | 200px | 최소 200px, 링크 한 줄에 맞춰 자동 | 최소 200px, 링크 한 줄에 맞춰 자동, 최대 100% |
| Profile 날짜 열 폭 | 112px | 112px | 날짜를 각 항목 맨 아래에 배치 |
| 연구 관심사 | 2열 | 2열 | 1열 |
| 멤버 표 열 비율 | 50 / 30 / 20% | 50 / 30 / 20% | 43 / 35 / 22% |

- 넓은 화면의 프로필과 본문 사이 간격은 **48px 고정**(`--layout-gap`)이다. 화면이 커져도 간격을 늘리지 않는다. 본문 열은 `minmax(0, 1fr)`이다.
- `AcademicShell`은 Profile·Research·Lab 프로필에 `profile-secondary` 클래스를 부여한다. ≤900px에서는 이 프로필 전체를 `display: none`으로 숨긴다. 사진·이름·소속·링크·프로필 아래 선과 그 여백이 함께 사라지며 빈 공간을 남기지 않는다.
- 메뉴바는 모든 화면에서 상단 sticky이다. 넓은 화면 프로필도 sticky이며 top은 `메뉴바 높이 + 48px`이다. ≤900px의 프로필은 일반 문서 흐름을 따라 올라간다.
- 가장 좁은 화면(≤560px)에서는 사이트 이름과 메뉴 묶음을 각각 가로 가운데 정렬한다. 메뉴 간격은 화면 폭이 328px 이상이면 24px를 유지한다. 그보다 좁으면 화면 폭에서 304px를 뺀 값으로 줄이되 최소 8px를 유지한다. 예를 들어 320px 화면에서는 16px이다.
- 중간 화면과 모바일(≤900px)의 Home에서는 사진+정보 묶음 전체, 정보 텍스트, 링크 묶음을 가운데 정렬한다. 560px 경계에서 프로필의 텍스트 정렬을 변경하지 않는다. 공간이 부족하면 사진과 정보 묶음 사이에서 줄바꿈하되, Google Scholar·CV·Email은 항상 한 줄로 유지한다. 정보 영역은 최소 200px에서 링크 세 개가 들어갈 폭까지 자연스럽게 넓어진다.
- 사진 비율은 198:246이며 높이는 auto이다. 사진 폭은 테두리·padding을 포함한 외곽 폭으로, 넓은 화면은 200px, ≤900px는 모두 144px이다. 가장 좁은 화면에서도 사진을 추가로 축소하지 않는다.
- 프로필의 사진과 정보 사이 간격은 넓은 화면 세로 24px, 좁은 화면 가로 24px / 줄바꿈 시 세로 16px이다.
- 푸터 선은 사이트 콘텐츠 영역의 좌우 바깥 경계와 정렬하며, Back to top만 오른쪽에 둔다. `.site-layout` 하단 padding은 넓은 화면 32px, ≤900px는 24px이다. 넓은 화면에서 프로필이 본문보다 높으면 더 긴 열을 기준으로 푸터가 내려간다. 푸터 선 아래 링크까지 padding은 24px, 링크 아래 padding은 32px이다.
- Back to top 화살표는 공통 Arrow SVG의 위쪽 방향이며 크기 15px, 선 굵기 1.5, 텍스트와의 간격 8px이다. 이름·학교 표기를 푸터에 다시 추가하지 않는다.

### 프로필 링크 영역

순서는 **Google Scholar → CV → Email**이다. CV는 `/cv`를 새 탭(브라우저 설정에 따라 새 창)으로 여는 링크이며 문서 아이콘을 사용한다. `target="_blank"`, `rel="noopener noreferrer"`를 유지한다. 링크를 페이지 하단에 중복해서 넣지 않는다. 좁은 화면의 프로필 표시·숨김 규칙은 그대로 적용한다.

세 링크의 색상·밑줄·아이콘 이동은 3절의 공통 규칙을 따른다. `.profile-link-label`은 Scholar·CV·Email에 동일하게 사용하고 Email 버튼도 같은 선택자에 포함한다.

| 항목 | 넓은 화면 | ≤900px |
|---|---|---|
| 소속 아래 링크 묶음의 margin-top | 12px | 8px |
| 링크 묶음 위 선 / padding-top | 선 없음 / 0px | 선 없음 / 0px |
| 링크 배치 | 세로, 폭 200px, gap 4px | 가로 한 줄, gap 16px, 링크·라벨 줄바꿈 없음 |
| 각 링크 세로 padding | 0px | 0px |
| 각 링크 최소 높이 | 24px | 24px |
| 텍스트와 아이콘 사이 간격 | 좌우 양끝 정렬 | 8px |

링크 텍스트는 12px/24px이다. 세로로 나열할 때 줄높이 24px + 사이 간격 4px로 프로필 소속 행과 같은 28px 간격을 사용한다. 링크마다 추가 padding을 더하지 않는다. 링크 간격을 수정하더라도 사진·이름·직함·소속의 크기나 여백은 별도 요청 없이 바꾸지 않는다. Scholar 화살표와 CV 문서 아이콘은 15px, Email 아이콘은 16px이며 ≤900px에서는 세 아이콘 모두 13px이다.

## 6. 공통 간격과 구분선

| 간격 변수 | 값 | 용도 |
|---|---|---|
| `--space-detail` | 4px | 제목→설명→보조 정보, 프로필 소속 행, 프로필 링크 세로 간격 |
| `--space-small` | 8px | 작은 요소·아이콘 간격 |
| `--space-label` | 12px | 프로필 이름 아래, 표 셀 padding, Publications 주석 관련 간격 |
| `--space-inline` | 16px | 날짜 열과 내용 열 사이, 인라인 요소 |
| `--space-item` | 24px | 일반 섹션 제목 아래, 사진 아래, 관심사 열 간격 |
| `--space-section` | 28px, 모바일 24px | 섹션 선 전후 여백 |
| `--space-list` | 20px, 모바일 16px | 항목 선 전후 여백 |

| 구분선 역할 | 굵기 / 색 | 적용 |
|---|---|---|
| 큰 섹션 구분 | 1.5px / `#c4d2e4` | Recent News·Profile 섹션, Publications 시작, Current members↔Alumni, ≤900px의 Home 프로필 아래, 모든 화면의 Back to top 위 |
| 목록 항목 구분 | 1px / `#edf1f6` | 경력·논문 항목 사이, 연구 관심사 행 사이(첫 행 제외) |
| 일반 경계 | 1px / `#e0e7f0` | 메뉴바 아래, 사진, 표 머리글 |
| 선택된 메뉴 표시 | 2px / 파랑 | 활성 메뉴 아래 |

본문의 섹션 선 전후 여백은 28px(모바일 24px), 목록 선 전후 여백은 20px(모바일 16px)이다. Home의 프로필과 Welcome! 사이 구분선은 Recent News 위 구분선과 같은 `--space-section`을 사용해 위아래에 각각 좁은 모드 28px, 가장 좁은 모드 24px를 둔다. 푸터 선의 여백은 5절의 하단 padding 규칙을 사용한다.

마지막 항목의 불필요한 하단 padding은 제거한다. 구성원 개인 사이에는 선을 넣지 않아 Current members와 Alumni의 구분이 더 잘 보이게 한다.

## 7. 페이지별 구성

### Home

순서: **Welcome! → Recent News**.

- Welcome!과 Recent News는 24px 제목을 사용한다. 소개 문단은 16px/28px이다. 지도교수 이름 링크는 같은 크기의 Arial 600 남색이며 공통 15px 바깥쪽 화살표를 표시한다.
- `app/page.tsx`의 뉴스는 `2026.11` 형식으로 최신 월부터 나열한다. 넓은 화면·중간 화면의 날짜 열은 64px이고, 날짜 열과 본문 사이에는 공통 16px 간격을 둔다. 모바일에서는 각 뉴스의 날짜를 문장 위에 표시한다.
- 뉴스 문장은 저널명 링크를 포함해 Arial 14px/24px 일반체로 표시한다. 논문 게재 소식은 저널명을 포함한 문장으로 작성하고 논문 제목은 생략한다. 날짜는 기존 12px 보조 정보 크기를 사용한다.
- 학생 이름, 저널명, 연구비 명칭은 굵기 600의 남색 `--navy`로 강조한다. 논문 주소는 저널명에 연결해 새 탭(브라우저 설정에 따라 새 창)에서 열고, 학생 이름과 연구비에는 링크를 달지 않는다. 저널명 옆에는 공통 15px 바깥쪽 화살표를 표시하며, hover 시 오른쪽과 위쪽으로 각각 1px 이동한다.

### Profile

순서: **Employment → Education → Grants → Appointment → Awards**.

- 화면에는 별도 Profile 제목이나 첫 구분선을 표시하지 않는다. 스크린 리더용 페이지 제목은 유지한다.

- 경력 설명 등 일반 본문은 14px/24px이다.
- 기록은 `RecordRow(date, title, details, location?)`를 재사용한다. 넓은 화면·중간 화면에서는 왼쪽 날짜 열과 오른쪽 내용 열(제목 → 소속/설명 → 장소/기관)을 사용한다.
- 경력·학력·과제·보직·수상 내용은 `app/academic-data.ts`의 `academicSections`에서 한 번만 수정한다. Profile과 CV가 같은 배열을 읽는다. Welcome 소개문은 `app/page.tsx`에 별도로 유지한다.
- 날짜 열 너비는 넓은 화면·중간 화면 모두 112px이며, 내용 열과의 간격은 16px. 가장 좁은 화면(≤560px)에서는 제목 → 소속/설명 → 장소/기관 → 날짜 순으로 배치한다. 날짜는 내용 전체 아래에 4px 간격으로 놓고 글자 크기 12px, 줄높이 24px, 보조색을 사용한다. 장소/기관이 없는 항목도 날짜를 맨 아래에 놓는다.
- Employment·Education·Awards는 현재 최신 기록부터 나열한다. 새 기록 추가 시 같은 방식으로 편집한다.
- 기간 표기는 기존 `2024 ~ Present`, `2018 ~ 2023`, `2026.03 ~ 2031.02` 형식을 따른다. 사실 확인 없이 날짜를 바꾸지 않는다.

### Research

순서: **Research interests → Publications**.

- 관심사 순서: Semiparametric theory → Incomplete data analysis → Distribution shift → Optimal sampling.
- Research interests 자체는 24px/32px 섹션 제목이다. `.research-heading > h1`에서 크기와 줄높이 모두 섹션 변수를 참조한다. 각 관심사 제목은 16px/600, 설명은 14px이며 둘 사이 간격은 4px이다.
- Research interests 제목과 첫 관심사 행 사이는 모든 화면에서 24px이다. 첫 행 위에는 얇은 선과 추가 padding을 넣지 않는다. 2열 화면은 첫 두 항목, 1열 화면은 첫 항목만 첫 행이며 이후 행 사이에는 기존 목록 구분선을 유지한다.
- 논문 목록은 연도 열 48px + 간격 16px + 내용 열이다. 모바일에서도 연도 열을 유지한다.
- 논문 내부는 **제목 → 저자 → 저널명/상태**, 각 줄 사이 margin 4px, 줄높이 24px이다.
- 최신 연도부터 배열에 작성한다. 현재 `2026+`는 투고 중인 논문 표기이며, 같은 연도 안의 순서는 별도 지시 없이 변경하지 않는다.
- 제목 링크, 저자 순서, DOI/arXiv/JMLR 주소, 저널명을 정확히 보존한다.
- 저자 기호: `*` corresponding author, `⁺` lab member, `⁼` co-first author. 현재 저자 문자열에 들어 있는 기호를 그대로 사용한다. 별도 `<sup>` 스타일로 변경하지 않았다.
- 범례는 `* ⭢ corresponding author; ⁺ ⭢ lab member; ⁼ ⭢ co-first author`이며 하나의 문단으로 자연스럽게 줄바꿈한다. Publications 제목 아래 12px에 둔다. 범례의 화살표 제거·묶음 단위 줄바꿈은 적용하지 않았다.
- 일반 섹션 제목 아래 간격은 24px이나 Publications는 범례가 있어 제목→범례 12px, 범례→목록 24px이다.
- 관심사와 논문 내용은 `app/academic-data.ts`의 `interests`, `publications` 배열에서 수정한다. Research와 CV가 같은 배열을 읽는다. 홈페이지의 `submitted`만 `.publication-status`이며 실제 저널명은 `.journal`이다.

### CV — 홈페이지 데이터 연동

- `/cv`는 독립된 CV 문서 화면이다. 프로필의 **Google Scholar와 Email 사이에 있는 CV 링크**로 새 탭에서 연다. 홈페이지 디자인·메뉴 구조는 유지한다.
- 이름·직함·소속은 `app/academic-data.ts`의 `profile`에서 읽는다. 프로필과 CV에 같은 정보를 중복 작성하지 않는다.
- CV 문서 맨 위는 이름 → 직함 → 소속으로 시작한다. `Curriculum vitae` 표제와 홈페이지 주소·Google Scholar 링크는 화면과 인쇄 모두 표시하지 않는다. 상단 도구 영역에는 오른쪽 정렬된 `Print / Save PDF` 버튼만 두며, 돌아가기 링크와 출력 안내 문구는 표시하지 않는다.
- 포함 순서: Employment → Education → Grants → Appointment → Awards → Research interests → Publications. 데이터와 항목 순서는 홈페이지와 동일하다.
- **Welcome 제목과 소개문 전체, Lab 페이지 내용은 제외**한다. 사진·메뉴·sticky 프로필을 CV 본문에 넣지 않는다. 기존 이메일 주소 숨김 원칙을 유지하며 CV에도 평문 이메일을 노출하지 않는다.
- `Print / Save PDF` 버튼은 글꼴 준비를 기다린 뒤 브라우저 인쇄 창을 연다. 준비 중에는 `Preparing…`으로 표시하고 중복 클릭을 막는다. 사용자가 프린터 또는 PDF 저장을 선택한다. 고정 PDF 파일을 별도로 관리하거나 클릭 즉시 다운로드한다고 표시하지 않는다.
- CV 글자 크기는 **짝수 정수**만 사용한다. 화면의 글자 크기·줄높이는 홈페이지의 공통 역할 변수(`--text-*`, `--line-*`)를 참조한다. `.cv-page`의 `--cv-*` 변수에서 연결하고 인쇄 매체에서 더 작은 CV 전용 값으로 덮어쓴다. 여백은 아래 CV 규칙을 유지하며 별도의 개별 숫자 예외를 만들지 않는다.

| 논문 연도 열 / 내용과의 gap | 48px / 16px | 48px / 16px, 연도 왼쪽 | 34pt / 10pt |

- 버튼은 오른쪽 정렬이며 파란 배경·흰 글씨·1px 파란 테두리, padding 세로 8px·가로 16px, 모서리 2px이다. hover 배경은 남색이다. 홈페이지의 텍스트 링크 hover 규칙을 버튼에 추가하지 않는다.
- CV 화면 색상은 홈페이지 팔레트를 따른다. 인쇄 본문은 `#222`, 이름·섹션·항목 제목은 남색, 날짜·장소·상태·주석은 회청색이며 페이지 머리말과 쪽 번호는 `#506073`이다. 구분선은 화면 `#c4d2e4`, 인쇄 `#aeb9c8`이다.
- CV 논문 링크는 제목의 색상을 유지하고 hover 시 밑줄만 표시한다(아래 간격 4px, 두께는 브라우저 기본값). 홈페이지 논문 링크의 파란색 전환·화살표를 CV에 자동 적용하지 않는다.

- 화면에서는 홈페이지와 같이 항목 제목 16px, 소속·설명·저자 이름 14px의 구분을 유지한다. 인쇄에서만 두 역할을 작은 쪽인 10pt로 통일하고 굵기 600/400으로 구분한다. 인쇄용 `--cv-text-item`은 `--cv-text-body`를 참조해 크기가 서로 달라지지 않도록 한다.
- 본문·항목 제목·저자·저널·보조 정보의 줄높이는 화면 24px, 인쇄 14pt로 유지한다. 인쇄용 10pt 본문의 줄높이는 글자 크기의 1.4배이며, 요소 사이의 별도 여백은 위 간격 표를 따른다. 화면의 문서 표제는 홈페이지의 최상위 제목 역할(28px)을 사용하며, 사이드바 프로필 이름(24px)과는 역할이 다르다.
- 구분선은 섹션 사이에만 사용하며 화면 1px, 인쇄 0.6pt이다. 개별 항목은 같은 역할의 여백으로 구분한다. 마지막 섹션 뒤에는 추가 padding을 넣지 않는다.
- A4, 상하 16mm·좌우 18mm의 인쇄 여백은 유지한다. 화면과 인쇄의 크기 단위는 각각 px와 pt로 관리하며, 홈페이지의 기존 글자 크기·간격을 CV 수정으로 변경하지 않는다.
- 인쇄에서 버튼을 숨기고 `break-inside: avoid`, `break-after: avoid`, `orphans: 2`, `widows: 2`로 항목 도중의 페이지 나눔과 제목만 남는 페이지를 최소화한다. 실제 나눔은 브라우저와 항목 길이에 따라 출력 결과를 확인한다. 링크는 PDF에서도 유지한다.
- PDF 머리말은 `@page curriculum-vitae`의 `@top-right`에 `Seong-ho Lee | CV`를 Arial 8pt로 오른쪽 정렬한다. 오른쪽 아래 여백의 `@bottom-right`에는 `Page 1 of 2` 형식으로 현재 쪽과 전체 쪽 수를 Arial 8pt로 표시한다. 머리말과 쪽 번호는 인쇄 페이지 여백에 표시한다.
- 인쇄 창에서 브라우저의 **머리글 및 바닥글을 꺼야** 자동 날짜·중앙 제목·URL과 겹치지 않는다. CSS 페이지 여백 상자를 지원하는 브라우저(Chrome 131 이상 등)에서 사용하며, 브라우저가 자동 생성하는 머리말 자체의 위치를 제어하는 기능으로 설명하지 않는다.
- CV 화면의 **≤560px에서만** 경력·학력 등의 날짜를 항목 아래에 표시한다. 논문 연도는 Research와 CV가 공통 `--year-width`(48px)를 사용하고 모바일에서도 왼쪽에 둔다. 인쇄에서는 날짜와 내용의 2열 구성을 사용한다. CV 전용 CSS는 `.cv-*`로 범위를 한정한다.
- 홈페이지를 업데이트·배포하면 CV도 같은 데이터로 갱신된다. 이미 저장한 PDF는 갱신되지 않으므로 필요한 시점에 다시 출력한다.

### Lab

순서: **IDEA Lab + 설명 → Current members → Alumni**.

- 표제는 정확히 `IDEA Lab`, 설명은 `for Incomplete Data Efficient Analysis`이다.
- IDEA Lab은 28px Garamond 600, 설명은 14px Arial 400이다. 넓을 때 같은 줄의 baseline에 두고 가로 gap 16px, 공간 부족 시 세로 gap 8px로 줄바꿈한다.
- IDEA와 Lab 사이에 강제 줄바꿈을 넣지 않는다. 장식적인 로고·강조 도형은 사용하지 않는다.
- Lab 표제와 Current members 사이에는 구분선을 넣지 않는다.
- Current members와 Alumni 각각 **Name / Program / Period** 3열 표를 쓴다. 과정별 별도 소제목·그룹 표는 만들지 않는다.
- Name·Program은 왼쪽, Period는 오른쪽 정렬. 표 셀은 baseline 기준이다.
- 영문 이름 14px/600, 한글 이름 12px/400, 과정 14px/400, 기간 12px/400으로 구분한다. 표 안의 줄높이는 모두 24px이다.
- 넓은 화면의 영문·한글 이름 사이 gap은 12px이며 필요하면 줄바꿈한다. 가장 좁은 화면(≤560px)은 한글 이름을 아래 줄에 놓고 gap 0px로 붙인다. 두 이름의 줄높이는 각각 24px를 유지한다.
- 표 셀 padding은 세로 12px, 오른쪽 12px(모바일 8px)이다. 마지막 열 오른쪽 padding, 마지막 행 하단 padding은 0이다.
- 인턴 과정은 `Internship`, 박선현의 과정은 `MS/PhD integrated`로 표기한다.

### Lab 멤버 정렬 — 반드시 유지

다음 기준을 **1순위 → 2순위 → 3순위**로 적용한다. 기간이 더 최신이어도 상위 과정보다 앞에 배치하지 않는다.

| 우선순위 | Current members | Alumni |
|---|---|---|
| 1. 과정 | **PhD → MS → Internship** | **PhD → MS → Internship** |
| 2. Period | 입학·참여 시작 시점이 **오래된 순 → 최근 순** | 졸업·참여 종료 시점이 **최근 순 → 과거 순** |
| 3. 한글 이름 | 성 기준 가나다순, 성이 같으면 이름 가나다순 | 동일 |

- `MS/PhD integrated`는 PhD와 같은 첫 번째 그룹이다. 두 표기 간 별도 우선순위를 두지 않고 기간·한글 이름으로 이어서 정렬한다.
- 예: Current members의 MS·2026-1은 **남관호 → 이채원 → 최재우**.
- 예: Alumni의 Internship·2026-1은 **변건호 → 안상준**, 그 다음 2025-2의 이수아.
- 한글 이름이 없는 사람은 음역을 임의로 만들지 않는다. 과정·기간이 같은 경우에만 한글 이름이 있는 구성원 다음에 영문 이름 순으로 둔다. 이는 미지정 사례의 구현 기본값이며 추후 지시 시 변경할 수 있다.
- 정렬은 `sortMembers(members, "current" | "alumni")`가 자동 처리한다. 한글 이름은 `localeCompare(..., "ko")`로 비교하며 입력 배열은 변경하지 않는다.

멤버 추가·수정은 `app/lab/members.ts`에서 한다.

```ts
{ name: "Sunhyun Park", korean: "박선현", program: "MS/PhD integrated", period: "2025-1 ~" }
```

`period`는 학기 형식 `YYYY-1` / `YYYY-2`를 사용한다. 현재 멤버는 `2025-1 ~`, 졸업자는 `~ 2026-1`, 한 학기 인턴은 `2026-1`처럼 표시한다. 범위가 있으면 `2023-1 ~ 2026-1`로 기록한다. Current members는 첫 학기, Alumni는 마지막 학기를 정렬키로 쓴다. 졸업·종료 시 해당 객체를 Alumni로 옮기고 종료 학기를 갱신한다. 새 과정·기간 형식을 도입할 때는 타입, 정렬 함수, 테스트, 이 문서를 함께 검토한다.

## 8. 링크·접근성·이메일

- 외부 링크는 기존 주소를 유지하고 새 탭에는 `rel="noopener noreferrer"`를 사용한다.
- Email에는 주소를 표시하지 않는다. 클릭 시에만 인코딩된 주소를 복원해 메일 앱을 연다. 평문 주소나 `mailto:`를 초기 HTML의 링크·title·aria-label에 넣지 않는다.
- Base64는 단순 HTML 수집을 줄이는 난독화이며 암호화가 아니다. JavaScript를 분석하는 수집까지 완전히 막는다고 설명하지 않는다.
- Email 주소 변경은 `app/email-link.tsx`의 인코딩 값에서 처리한다. 주소를 INSTRUCTION·프로필 텍스트·공통 데이터에 평문으로 추가하지 않는다.
- 메뉴의 `aria-current`, Skip to main content, 표의 `scope`와 `aria-labelledby`, 사진의 alt, 버튼의 키보드 동작, focus 표시를 유지한다.
- `prefers-reduced-motion`에서는 전환 효과와 부드러운 스크롤을 비활성화한다.
- 인쇄 시 메뉴·푸터·프로필 링크를 숨기고 프로필을 일반 흐름에 배치한다. 인쇄용 사진 폭은 100px이다. 인쇄 CSS는 화면용 프로필 숨김을 덮어써 네 페이지 모두 프로필을 표시한다.

## 9. 업데이트 절차와 검증

1. 최신 소스를 연 뒤 이 문서와 실제 변경 대상 파일을 확인한다. 기존 미완료 변경을 덮어쓰지 않는다.
2. 내용 수정은 해당 데이터·페이지 파일에서, 디자인 수정은 공통 CSS 변수·컴포넌트에서 처리한다. 별도 지시 없는 페이지까지 시각 양식을 바꾸지 않는다.
3. 변경 범위에 맞춰 아래 검증을 수행한다. 통과한 검증은 새로운 변경이나 문제가 없으면 반복하지 않는다.
4. 앱을 바꾼 경우 `preview`에 커밋하고 10절의 검토용 페이지를 확인한다. 검토 링크와 커밋을 사용자에게 보내고 승인받은 뒤 해당 커밋을 `main`에 반영한다. 같은 승인본의 정적 결과물을 `gh-pages`에 배포하고 두 공개 주소를 확인한다.
5. 승인된 기준이 바뀌었으면 INSTRUCTION도 같은 변경에 포함한다. INSTRUCTION만 수정한 경우 문서와 소스 기록을 저장하며 화면을 바꾸거나 다시 디자인하지 않는다.

| 변경 범위 | 검증 |
|---|---|
| INSTRUCTION만 변경 | `git diff --check`, 실제 코드·대화와 수치 및 규칙 대조. 앱 재빌드·화면 재검증 불필요 |
| 콘텐츠·레이아웃·공통 컴포넌트 | 관련 페이지 화면 확인 및 `npm run build`. 공통 스타일이면 네 페이지 확인 |
| 글꼴·글꼴 로딩 | 빌드 후 `node scripts/check-font-assets.mjs`, 새로고침 시 글꼴 표시 확인 |
| 링크 반응 | 기본·hover·키보드 focus를 3절과 대조. Email은 실제 메일 앱을 열지 않고 아이콘·밑줄을 확인하며, Back to top과 논문 링크도 별도로 확인 |
| CV 서식·출력 | 화면과 `@media print`를 나누어 확인. 인쇄 가능한 환경에서는 A4 PDF의 머리말·쪽 번호·페이지 나눔·버튼 숨김을 확인하고 불가능하면 한계를 기록 |
| Lab 멤버 데이터·정렬 | `node --experimental-strip-types --test tests/lab-members.test.mjs`, Lab 표 확인 및 빌드 |

브라우저 검증 환경을 사용할 수 없으면 그 한계를 기록하고, 확인하지 않은 화면을 확인했다고 보고하지 않는다.

CV 추가 시 기존 경력 기록 9개·연구 관심사 4개·논문 8개의 데이터가 변경 없이 공통 파일로 옮겨졌음을 대조했다. CV 링크와 페이지, 좁은 화면, 빌드·폰트 검증은 통과했다. 원격 검증 브라우저에서 인쇄 메뉴가 비활성화되어 실제 PDF 저장 결과와 페이지 나눔은 확인하지 못했다. 인쇄 서식 변경 시에는 인쇄를 지원하는 브라우저에서 이를 확인한다.

### 하나의 공개 저장소

- 원본 코드와 문서는 **`seongholee5/seongholee5.github.io`** 하나에서 관리한다. 검토는 Cloudflare Pages에서 진행하며, 승인본은 Cloudflare Pages와 GitHub Pages에 게시한다.
- 유지보수 문서는 **`docs/INSTRUCTION.md`**이다. 루트 **`README.md`는 빈 파일**로 유지해 저장소 메인 화면에 긴 유지보수 문서가 표시되지 않게 한다. 문서 자체는 공개 저장소에서 직접 열 수 있다.
- 디자인·간격·정렬·CV 규칙을 바꾸면 관련 코드와 `docs/INSTRUCTION.md`를 같은 변경으로 갱신한다. 홈페이지 메뉴에는 이 문서 링크를 추가하지 않는다.
- `app/`, `public/`, 빌드 설정, 검사 스크립트와 테스트가 편집 원본이다. `dist/client/`는 생성된 배포 결과물이다. 원본 브랜치에는 추가하지 않고, GitHub Pages 배포 시 현재 빌드의 정적 파일만 `gh-pages` 루트에 게시한다.
- Cloudflare Pages 프로젝트 하나가 이 저장소를 사용한다. 공개 브랜치는 `main`이고 검토 브랜치는 `preview`이다. 빌드 명령은 `npm test && npm run typecheck && npm run build`, 출력 폴더는 `dist/client`, Node.js는 24이다.
- 새 변경은 `main`을 기준으로 작업하고 `preview`에 올린다. 검토용 페이지에서 변경을 확인한 뒤 사용자에게 링크와 커밋을 보낸다. 같은 검토용 주소에 새 변경을 추가했다면 그 커밋에 대해 다시 승인받는다.
- 사용자가 승인한 커밋을 `main`에 반영하면 Cloudflare가 공개 버전을 빌드한다. 승인받기 전에는 `main`에 변경을 올리지 않는다. `main`이 검토 이후에 바뀌면 변경을 합친 결과를 다시 검토한다.
- 검토 주소는 링크로 열 수 있다. GitHub 저장소와 검토용 페이지에는 비공개 자료를 올리지 않는다.
- GitHub Pages는 `Deploy from a branch`의 `gh-pages` / `(root)`에서 정적 파일을 제공한다. `seongholee5.github.io`는 주소를 유지하며, Cloudflare 공개 주소와 독립적으로 배포된다. 저장소에 별도 Actions 워크플로 파일을 두지 않는다.
- 승인본 공개 시 `main`의 소스로 빌드하고 검사를 통과한 `dist/client/`의 내용과 `.nojekyll`을 `gh-pages`에 올린다. GitHub가 기본 `pages build and deployment` 실행을 생성한다. `github-pages` 환경의 `Required reviewers`는 꺼져 있다. 사용자에게 공개 지시를 받은 뒤에만 `gh-pages`를 갱신하며, 갱신 후 GitHub가 별도 승인 단계 없이 게시한다. 배포 완료 후 `github.io`에서 Home, Profile, Research, Lab, CV를 확인한다. 문서만 수정했으면 공개 정적 파일을 다시 게시할 필요는 없다.
- 다른 저장소로 복사하거나 별도의 배포용 토큰을 관리하지 않는다.

### 실행과 검증

- Node.js **24 권장**, 최소 22.13, React/TypeScript + Vinext 기반이다. 공개 사이트에 데이터베이스·서버 런타임·ChatGPT 로그인은 필요하지 않다.
- 설치 `npm ci`, 개발 `npm run dev`, 정렬 검사 `npm test`, 타입 검사 `npm run typecheck`, 정적 빌드·검사 `npm run build`.
- 홈페이지와 CV는 같은 `app/academic-data.ts`를 사용한다.
- `next.config.ts`는 `output: "export"`, `trailingSlash: false`이다. `scripts/check-static-export.mjs`가 `/profile/`, `/research/`, `/lab/`, `/cv/`의 `index.html`을 생성한다. 각 페이지 직접 접속과 새로고침을 확인한다.
- `.nojekyll`을 생성해 `_next/` 자산이 포함되게 한다. 빌드 검사에서 다섯 페이지·로컬 자산·CV 제외 항목·새 창 링크·편집 원본 및 소스맵 제외를 확인한다. 유지보수 문서는 홈페이지 빌드 결과에 포함하지 않는다.
- 두 공개 사이트와 검토용 사이트는 각 도메인의 루트에 배포한다. 프로젝트 하위 경로로 바꾸면 `/`로 시작하는 링크·이미지·CSS·JS 경로를 조정하고 재검증한다.
- 토큰·인증정보·환경 비밀값은 문서나 Git에 저장하지 않는다. `node_modules/`, `dist/`, `.env*`, 임시 미리보기 설정은 원본 버전 관리에서 제외한다.
- 기존 Sites 소스와 공개 범위는 별도로 유지한다.
